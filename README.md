# content-research

이 저장소에는 두 가지가 들어 있습니다.

1. **유튜브 파이프라인** (`api/cron/fetch-youtube.js`) — 매일 아침 6시(KST) config 탭의 키워드로 "구독자 대비 조회수 배율이 높은" 영상을 찾아 contents 탭에 저장
2. **나다운타운 시민 확인 · 설문 사이트** (`public/index.html` + `api/survey/*`) — 수강생이 성함 + 연락처 뒷 4자리로 본인 확인 → 설문 작성 → 구글시트 저장 → 챌린지 단톡방 링크 안내

---

## 파일 구조

```
public/index.html            ← 나다운타운 페이지 (3D 히어로 + 시민 확인 + 설문 4단계 + 완료 화면)
api/survey/verify.js         ← POST 시민 확인 (명단 대조)
api/survey/submit.js         ← POST 설문 제출 (명단 재대조 → 시트 저장 → 단톡 링크 반환)
api/survey/setup.js          ← GET  최초 1회 시트 양식(탭·헤더) 생성 (SETUP_SECRET 필요)
api/cron/fetch-youtube.js    ← 유튜브 크론
lib/sheets.js                ← 구글시트 읽기/쓰기 (두 기능 공용)
lib/survey.js                ← 명단 대조·검증·행 조립 (순수 로직)
lib/citizen.js               ← verify/submit 공용 흐름
lib/ratelimit.js             ← 무작위 대입 방지용 간단한 요청 제한
scripts/dev-server.js        ← 로컬 실행 (가짜 시트, 구글 인증 불필요)
scripts/e2e-check.js         ← 브라우저로 전체 흐름 자동 점검
test/                        ← 단위 테스트 (node --test)
vercel.json                  ← 크론 스케줄
```

## 나다운타운 사이트 — 처음 세팅하는 순서

### 1) 환경변수 (Vercel 프로젝트 설정 → Environment Variables)

| 이름 | 설명 |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_KEY` | 서비스 계정 JSON 전체 (기존 유튜브 파이프라인과 같은 값 재사용) |
| `SETUP_SECRET` | 시트 양식 생성 엔드포인트를 보호하는 비밀 문자열. 아무 긴 랜덤 문자열 (예: 32자) |
| `GOOGLE_ROSTER_SHEET_ID` | (선택) 수강생 명단 시트 ID. 비워두면 `13yXgwE4lsxQ-t1hXzz-9hHIkifN_ANaHAkcpeNOz50o` |
| `GOOGLE_SURVEY_SHEET_ID` | (선택) 챌린지신청자(설문 결과) 시트 ID. 비워두면 `12oqxXE3giBnlTjxLdhOePiyK4Ml47dkQK_39VGGgffE` |

### 2) 구글시트 공유 (보안의 핵심)

서비스 계정 이메일은 `GOOGLE_SERVICE_ACCOUNT_KEY` JSON 안의 `client_email` 값입니다 (`xxx@xxx.iam.gserviceaccount.com`).

| 시트 | 공유 대상 | 서비스 계정 권한 |
|---|---|---|
| **수강생 명단** (시민 확인용) | 본인 계정만 | 세팅 중엔 **편집자**, 세팅 끝나면 **뷰어**로 내림 (앱은 읽기만 함) |
| **챌린지신청자** (설문 결과) | 본인 + 결과를 봐야 하는 최소 인원 | **편집자** (앱이 행을 추가함) |

두 시트 모두:
- "링크가 있는 모든 사용자" 공유는 **끄기** (제한됨 상태 유지)
- 공유는 이메일 지정으로만
- 명단 시트는 결과 시트와 **파일 자체를 분리**해 둔 상태이므로, 결과 시트를 조교에게 공유해도 명단(전체 연락처)은 노출되지 않음

### 3) 배포 후 시트 양식 만들기 (최초 1회)

브라우저 주소창에 (SETUP_SECRET 값을 넣어서):

```
https://<프로젝트이름>.vercel.app/api/survey/setup?key=<SETUP_SECRET>
```

정상이면 아래처럼 응답하고, 두 시트에 탭과 헤더(굵게, 첫 행 고정)가 생깁니다. 이미 있으면 건드리지 않습니다.

```json
{ "ok": true, "roster": { "created": ["수강생명단", "챌린지링크"], ... }, "survey": { ... } }
```

끝나면 **수강생 명단 시트의 서비스 계정 권한을 뷰어로 바꿉니다.**

### 4) 시트에 내용 채우기

**수강생 명단 시트 → `수강생명단` 탭**

| 이름 | 연락처 | 기수 | 비고 |
|---|---|---|---|
| 홍길동 | 010-1234-5678 | 3기 | |

- 이름은 수강생이 입력하는 성함과 공백 무시하고 완전히 같아야 함
- 연락처는 하이픈 있어도/없어도 됨 (끝 4자리만 비교)
- 기수를 적어두면 설문에서 자동으로 채워지고 잠김. 비워두면 수강생이 직접 입력
- 이름 + 끝 4자리가 같은 사람이 둘 이상이면 "확인 불가" 처리되니 비고에 메모하고 연락처를 확인해 주세요

**수강생 명단 시트 → `챌린지링크` 탭**

| 기수 | 카카오톡 단톡 링크 | 활성(TRUE/FALSE) | 메모 |
|---|---|---|---|
| 전체 | https://open.kakao.com/o/... | TRUE | 기수별 링크가 없을 때 쓰는 기본 링크 |
| 3기 | https://open.kakao.com/o/... | TRUE | |

- 기수에 맞는 행이 없으면 `전체` 행의 링크를 씀
- 링크가 비어 있으면 완료 화면에 "준비되는 대로 안내" 문구가 뜸. 나중에 링크를 넣으면, 수강생이 다시 시민 확인만 해도 바로 링크가 보임 (이미 제출한 사람은 설문을 다시 쓰지 않음)
- 활성 칸을 비워두면 TRUE로 간주, `FALSE`로 쓰면 그 링크는 무시

**챌린지신청자 시트 → `설문응답` 탭** (앱이 자동으로 채움)

| 제출일시 | 기수 | 성함 | 닉네임 | 연락처 | 연령대 | 성별 | 지역 | 전공 | 홍보·영업 문의용 링크 | 교육에서 도움된 점 및 성과 | 현재 고민 | 시도해본 노력과 한계 | 이후 커뮤니티에서 바라는 점 | 앞으로의 다짐 | 안내된 단톡 링크 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

- 연락처는 명단에 있던 값(전체 번호)이 저장됨 — 수강생이 다시 입력하지 않음

## 동작 흐름

```
[시민 입장하기] → 성함 + 뒷 4자리 → POST /api/survey/verify
   ├─ 명단 없음/중복 → 에러 문구
   ├─ 이미 제출함   → 바로 완료 화면(단톡 링크)
   └─ 확인됨        → 설문 4단계 (임시저장: 브라우저 localStorage)
                        → POST /api/survey/submit (명단 재대조 → 설문응답 탭에 추가 → 링크 반환)
                        → 완료 화면: 단톡방 입장 버튼 / 링크 없으면 안내 문구
```

보안 처리:
- 응답에는 매칭 여부·기수·마스킹된 연락처(`010-****-5678`)만 담고, 명단 원본은 절대 내려보내지 않음
- 제출 시점에도 명단을 다시 대조 (verify 우회 방지)
- 같은 IP에서 시민 확인 10회/10분, 제출 8회/10분 초과 시 429
- 서버 로그에 요청 본문(이름·연락처)을 남기지 않음
- 페이지에 `noindex` 메타 (검색 노출 방지)

## 로컬에서 돌려보기 (구글 인증 없이)

```
npm install
npm run dev:local          # http://localhost:3000  (가짜 명단: 홍길동/5678, 김영희/1111)
npm test                   # 단위 테스트
NODE_PATH=$(npm root -g) npm run e2e   # 브라우저 흐름 점검 (playwright 필요)
```

실제 시트로 확인하려면 `vercel dev` 또는 `REAL_SHEETS=1 GOOGLE_SERVICE_ACCOUNT_KEY=... npm run dev:local`.

## 유튜브 파이프라인 (기존)

배포 후 수동 실행:

```
https://<프로젝트이름>.vercel.app/api/cron/fetch-youtube
```

정상이면 `{ "success": true, "keywordsChecked": 9, "rowsAdded": 12 }` 형태로 응답하고 contents 탭에 행이 쌓입니다.
환경변수 `YOUTUBE_API_KEY`, `GOOGLE_SHEET_ID`, `CRON_SECRET`(선택)이 필요합니다.

## 문제가 생기면

- `SETUP_SECRET 환경변수를 먼저 설정하세요` → Vercel 환경변수 추가 후 재배포
- setup 응답에 `편집자로 공유되어 있는지 확인` → 해당 시트에 서비스 계정 이메일을 편집자로 공유
- 시민 확인이 계속 실패 → 명단 탭 이름이 `수강생명단`인지, 이름 철자/공백, 연락처 끝 4자리 확인
- 완료 화면에 링크가 안 뜸 → `챌린지링크` 탭에 해당 기수 또는 `전체` 행의 링크가 채워져 있는지, 활성이 FALSE가 아닌지 확인
- `GOOGLE_SERVICE_ACCOUNT_KEY 환경변수가 없습니다` → Vercel 환경변수 등록 여부와 Production 체크 확인
